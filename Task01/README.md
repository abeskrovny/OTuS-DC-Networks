# Задание 1. Диагностический маршрут

## Условие
Стенд не нужен. Нужны полчаса и голова.

### Ситуация
Мультивендорная EVPN-VXLAN фабрика: два спайна, шесть лифов, три вендора. Работает год, никто ничего не менял.

В понедельник утром приходит заявка: виртуалка, переехавшая между хостами в пятницу вечером, недоступна из соседней подсети. Внутри своей подсети пингуется нормально. Другие виртуалки на том же хосте работают.
Первая линия проверила: линки в порядке, аплинки не флапали, на гипервизоре без изменений, порт в нужном VLAN.

### Что сдать
Документ на одну-две страницы:
1. Диагностический маршрут — 5-8 шагов. Для каждого: какая команда и на каком устройстве, какую гипотезу проверяете, что исключите при ожидаемом результате и что при неожиданном
2. Обоснование порядка — почему этот шаг первый, а не третий. Что отсекается дешевле всего
3. Три гипотезы, отброшенные сразу, без проверки, на основании условий задачи
4. Один вопрос, который вы бы задали заказчику или первой линии до начала

### Чего делать не надо
- Не нужен готовый ответ «проблема была в том-то». Условие сформулировано так, что однозначного ответа нет — это намеренно
- Не нужен конфиг
- Не нужно перечислять все известные команды. Оценивается порядок и обоснование, а не длина списка
